GitHub Pages で Space Quiz をデプロイして、誰でもアクセスできるようにします。Copilot はワークフローの準備とデプロイのガイドを行いますが、変更をレビューし、サイトが公開されたことを確認するのはユーザーです。

このレッスンでは、次の操作を行います。

- Copilot に GitHub Pages のデプロイを設定するよう依頼します。
- ワークフローとプルリクエストをレビューしてからマージします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、まだ簡単に試せる場所がありません。1 ファイルのサイトを GitHub Pages で公開すれば、サーバーや実行時依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストを作成すると、コードがコミットおよびプッシュされる場合があります。このプロンプトを送る前に、承認設定と送信先のリポジトリを確認してください。**すべて承認**が有効な場合、別途確認を求められないことがあります。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリに GitHub Pages のデプロイを準備してください。必要に応じて Web サイトをビルドし、変更が既定のブランチに反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更を含むプルリクエストを作成し、そのリンクと、必要な Pages の設定や権限を報告してください。マージ、自動マージの有効化、Pages の設定変更、デプロイは行わないでください。停止して、レビューを待ってください。
```

## ワークフローとプルリクエストをレビューする

1. README が、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限を含め、プルリクエストの変更をレビューします。
3. ワークフローが、未マージのプルリクエストではなく既定のブランチからデプロイすることを確認します。
4. 必要な修正を依頼して、更新された差分をレビューします。マージを許可する前に、必要なプルリクエスト チェックが成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトは、レビュー済みのプルリクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認してから送信してください。承認設定によっては、再確認なしでこれらの操作が実行されることがあります。

`<PR_NUMBER>` をレビューしたプルリクエスト番号に置き換えてから、次のプロンプトを別途送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使う GitHub Pages を有効にし、必要なチェックが成功した後にそのプルリクエストだけをマージし、デプロイが成功するまで監視してください。公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、私が承認または実行する必要がある操作を正確に説明してください。サイトが公開されるまでは、成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを行えない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは、タスクを完了したと見なさないでください。
